# Mobile cockpit plan — `gv mobile` v2

**Design:** [2026-07-06-mobile-design.md](2026-07-06-mobile-design.md)
(design-reviewed; full replacement of the old `gv mobile`, no
back-compat).
**Plan status:** plan-reviewed 2026-07-06; all findings applied
(notably: chatty lands *before* the backlog view that uses it, and the
e2e mobile smoke runs on a scratch tmux server).
**Branch:** `mobile-use` worktree (`~/git/.worktrees/grove/mobile-use`),
commit per task, `--ff-only` merge to main at the end.
**Gate for every task:** `go build ./... && go vet ./... && go test
./...` green, `gofmt -l .` empty. Task 6 and the final task also run
`e2e/dummy.sh`.

Current seams this plan builds on (verified against source):

- TUI model already carries `cfg/stateDir/label`
  (`internal/tui/tui.go:40-45`); actions are package-level injected vars
  `FinishTask`/`SpawnOrchestrator`/`AttachTask` (`tui.go:365-383`) wired
  from cmd/gv at startup. The cmd/gv implementations (`finishTask`
  `main.go:~1828`, `attachTask` `main.go:~1472`) use the startup-global
  `stateDir()` — that's what task 1 removes.
- `dash` dispatch takes no args (`main.go:234-235`).
- Refresh loop: `refreshMsg` handler re-schedules `tickEvery(m.stateDir,
  1s)` (`tui.go:173`), `prsMsg` re-schedules a 30s PR tick capturing
  `m.cfg` (`tui.go:179-181`) — the closures the epoch guard defends.
- `config.LoadAt`/`config.StateDirAt`: `internal/config/merge.go:29,108`.
- Verbs are `{Start, Review string}` (`internal/provider/provider.go:39-42`)
  and reach kickoff as a separate `Render` param at exactly one call
  site (`main.go:634`) — so chatty needs no template changes.
- github provider runs `gh` with `cmd.Dir = repoPath`
  (`internal/provider/github.go:39-51`); 15s cap (`github.go:40-41`);
  `Capabilities().CanList` gates backlog (linear = false); `ghURLRe`
  (`github.go:57`) is the pattern for pulling a number out of an issue
  URL.
- `tmux.KillSession` already exists (`internal/tmux/tmux.go:132-135`);
  the Mac's tmux 3.6a supports `#{pane_start_command}`.

## Task 1 — Scope plumbing: de-globalize the TUI's world

**Goal:** every TUI action targets the workspace the TUI is *showing*,
not the one `gv dash` started in. Pure refactor, no behavior change.

- Add `tui.Scope{Label, Root string; Cfg *config.Config; StateDir
  string}`; `Model` holds a `scope Scope` replacing the loose
  `cfg/stateDir/label` fields. `New`/`Run` take a `Scope`.
- Injected-var signatures gain explicit scope:
  - `FinishTask(cfg *config.Config, stateDir string, t *state.Task,
    force bool)`
  - `AttachTask(stateDir string, t *state.Task)`
  - `SpawnOrchestrator(scope Scope) (string, error)` — cmd/gv derives
    the cockpit session + orchestrator dir from `scope.Root`/`Label`
    (the `cockpitSessionFor`/`orchestratorDirFor` logic keyed off the
    scope, not startup `ambient.ws`; empty root = legacy global). This
    matters once task 4 lets a *desktop* dashboard switch workspaces —
    `O` must spawn into the cockpit of the workspace being viewed.
- cmd/gv callers updated: `cmdDone`/`cmdAttach` pass ambient
  `stateDir()`; **`cmdSweep` too** — it calls `finishTask` at
  `main.go:2036` and appends `EvTaskUntracked` via `stateDir()` at
  `main.go:2039`; both get the explicit param.
- **Verification:** compile + existing suite (note: `internal/tui/` has
  no tests today, so this task is verified by compilation) + grep-check
  that no `stateDir()`/`ambient` reference is reachable from a TUI
  callback.

**Commit:** `tui: actions take an explicit scope, not startup globals`

## Task 2 — `dash` args + mobile startup scope resolution

**Goal:** `gv dash --mobile [--workspace <label>]` boots without a
global config on a registry-only machine. **Plain `gv dash` is
untouched** — the resolver runs only under `--mobile`; desktop keeps
the ambient walk-up (`loadCfg()`/`stateDir()`, `main.go:264-282`).

- `cmdDashboard(args)`: flags `--mobile`, `--workspace <label>`.
- New tested decision func `workspace.ResolveStartupScope(label string,
  list []Workspace) (ws *Workspace, pick bool, err error)` in
  `internal/workspace/scope.go`. Table-driven tests:
  - explicit label → match; unknown label → error naming
    `gv workspaces`;
  - no label, exactly one alive workspace → it;
  - no label, ≥2 alive → `pick=true` (TUI boots into the workspace
    overlay, task 4);
  - dead-marker entries skipped (reuse `Alive`);
  - **registry non-empty but zero alive → same as empty**;
  - empty registry → `ws=nil, pick=false` → legacy global scope via
    `config.Load()`.
- `tui.Run` gains `Options{Mobile bool, StartInPicker bool}` (picker
  state lands in task 4; until then `StartInPicker` errors with "run
  `gv mobile <label>`" so this task ships alone).

**Commit:** `dash: --mobile/--workspace flags + registry-only startup
scope resolution`

## Task 3 — Narrow card layout

**Goal:** readable dashboard at 45–55 cols.

- `view.go`: when `m.width < 70 || m.opts.Mobile`, `viewAgents` renders
  two-line cards (glyph+ticket+status+age / repo+PR+CI+preview or
  question preview); activity feed clamps its ticket column to 14 in
  narrow mode (today it pads to `ticketColWidth()` ≤33,
  `view.go:59-70,145-152`).
- Extract pure renderers `cardLines(t, pr, live, width) []string` and
  `feedLine(item, ticketW, width) string`; TDD those. Test: 45-col
  render contains PR number + CI glyph; no line exceeds width; long
  tickets truncate with `…`.

**Commit:** `tui: two-line card layout + feed clamp under 70 cols`

## Task 4 — Refresh epoch guard + in-TUI workspace overlay (`w`)

**Goal:** switch workspaces without leaving the tmux session, without
stale-tick corruption.

- `Model.epoch int`; `refreshMsg`/`prsMsg` gain `epoch` stamped by the
  scheduling closure, **plus a `tick bool` origin flag**: one-shot
  refreshes (`v` `tui.go:299`, answer `tui.go:342`, `actionDoneMsg`
  `tui.go:197`) currently *also* hit the rescheduling handler and spawn
  extra 1s chains — only tick-originated messages may reschedule.
  `Update` drops messages where `msg.epoch != m.epoch` without
  rescheduling. TDD: stale msg → model unchanged, returned Cmd nil;
  current-epoch tick msg → applied + rescheduled; current-epoch
  non-tick msg → applied, **not** rescheduled.
- New `modeWorkspaces` overlay: rows from `workspace.LoadRegistry` +
  `ReadRollup` loaded via a `tea.Cmd` (rollups read files — off the
  Update path); `j/k` + `enter` selects; `esc` backs out; `w` opens it;
  `StartInPicker` boots into it with no backing scope (esc = quit
  there, flash explains).
- Selection: build the new Scope (`config.LoadAt(root)`,
  `config.StateDirAt(root)`, label, root), `m.epoch++`, reset
  `sel/detail/mode/prs`, emit fresh `refreshCmd`+`prsCmd` stamped with
  the new epoch. `config.LoadAt` failure → flash, stay on old scope.
- **Tests:** epoch/tick table above; switch resets selection and clears
  PR cache; picker rows render rollup counts (pure renderer, task-3
  pattern).

**Commit:** `tui: epoch-guarded refresh + w workspace overlay`

## Task 5 — `--chatty` grab flag + github chatty verbs

**Goal:** grabs can produce workers that narrate on the issue thread.
(Lands *before* the backlog view so the TUI can pass the flag from day
one.)

- `internal/provider`: `Chattify(v Verbs, kind string) Verbs` — for
  `kind == "github"`, returns v with milestone-comment instructions
  appended to `Start`/`Review`: short issue comment (1–3 lines) at plan
  settled / implementation done / tests green / PR opened; mirror any
  QUESTION/BLOCKED sentinel as an issue comment; never close the issue.
  Other kinds: returned unchanged.
- `cmdGrab`: `--chatty` flag; after provider resolution, `kind !=
  "github" && chatty` → stderr warn "chatty is github-only — ignored",
  proceed. Chatty verbs substitute at the single `Render` call site
  (`main.go:634`); no template changes.
- **Tests:** `Chattify` table (github gains the block; markdown/linear
  byte-identical); kickoff render test: github+chatty prompt contains
  the milestone and sentinel-mirror instructions; markdown+chatty does
  not.
- Manifest rows for the provider/kickoff surface additions
  (docs/seed-manifest.md) land here.

**Commit:** `grab: --chatty appends issue-narration verbs for github
workers`

## Task 6 — Replace `cmdMobile`

**Goal:** `gv mobile [label]` = kill-stale, build, attach; pane 0 runs
the absolute binary.

- New helpers in `internal/tmux/grove.go` (NOT `tmux.go` — stays
  byte-comparable): `PaneStartCommand(target) (string, error)`
  (`list-panes -F '#{pane_start_command}'`; verify against the local
  tmux, fall back to `pane_current_command` matching if a host lacks
  it) and `CreateSessionCmd(session, dir, command)` (pane 0 command set
  at creation, not SendKeys, so `PaneStartCommand` sees it and a shell
  rc can't eat it). Reuse the existing `tmux.KillSession`
  (`tmux.go:132-135`) — no duplicate.
- `cmdMobile(args)`: optional `<label>` positional →
  `ResolveStartupScope`. **Test seams:** session name from
  `GROVE_MOBILE_SESSION` env (default `grove-mobile`) and a hidden
  `--no-attach` flag — both exist for e2e only.
  1. If the session exists and pane 0's start command doesn't contain
     `dash --mobile` → `KillSession` (grove's own session; migration
     from the old design) and rebuild. Decision extracted as
     `needsRebuild(paneCmd string) bool` — unit-tested.
  2. Build: `CreateSessionCmd(session, dir, "<absolute-exe> dash
     --mobile [--workspace <label>]")` where `dir` = workspace root
     (label given / single workspace) else `$HOME`.
  3. `tmux.AttachSession` (skipped under `--no-attach`).
- **e2e (`e2e/dummy.sh`):** run the mobile smoke under a **scratch tmux
  server** — `TMUX_TMPDIR=$SCRATCH` isolates every tmux call gv makes
  from the real server (dummy.sh currently touches the live server for
  `pr-dummy`, lines 46-52 — the mobile smoke must not do that with a
  session named `grove-mobile`). With `--no-attach` +
  `GROVE_MOBILE_SESSION`: build → assert pane start command matches →
  re-run → still one session → **stale injection**: kill it and
  pre-create `tmux new-session -d -s <name> sleep 600` (a session whose
  pane 0 start command is not `dash --mobile`) → re-run `gv mobile` →
  assert rebuilt.

**Commit:** `mobile: rebuild-on-stale single-pane session running dash
--mobile`

## Task 7 — Backlog view + one-key grab (`g`)

**Goal:** "pick up unbrewed #142" = `g`, scroll/`/`-filter, `enter`.

- `modeBacklog`, entered via `g`. Per configured repo in scope:
  - `Capabilities().CanList` false (linear) → static "no backlog
    listing" row, skipped by the cursor.
  - else a `tea.Cmd` per repo → `backlogMsg{repo string, tasks
    []provider.Task, epoch int, err error}`; spinner row while
    in-flight; error → inline `!` row (never block Update — gh is
    15s-capped).
  - Provider construction mirrors `cmdGrab`'s per-repo resolution
    (`ProviderKindFor`); inject a `ListBacklog(cfg, repoName)` func var
    (the `FinishTask` pattern) so tests fake it without gh.
- Keys: `j/k` move, `/` filter (textinput; matches number and title
  substring), `enter` grab, `esc` back, `c` compose (task 8).
- Grab: injected `RunGrab(scope Scope, repo, id string) (out string,
  err error)` func var, wired from cmd/gv **closing over
  `os.Executable()`** — runs `<exe> grab <id> --repo <name> --chatty`
  with `cmd.Dir = scope.Root` (child's ambient walk-up lands in the
  right workspace), stdin `/dev/null` (a stray prompt must not hang the
  Cmd), combined output captured → `grabDoneMsg{id, out, err, epoch}`.
- Row shows `planting…` while running; on error the row flips to `!` +
  last non-empty output line and persists until `esc`/retry; on success
  flash `✓ planted <id>` (the task row arrives via the normal
  `EvTaskCreated` fold). The TUI appends no events itself.
- One grab at a time: an in-flight guard in the model is the actual
  serialization (run-setup's flock only covers the setup script inside
  the worker pane, not concurrent `worktree.Add`).
- **Tests:** pure update-machine tests with faked `ListBacklog`/
  `RunGrab`: loading→loaded ordering, CanList skip, filter narrowing,
  grab failure row persists, in-flight guard, stale-epoch `backlogMsg`
  dropped (workspace switched mid-list).

**Commit:** `tui: backlog view with async list + one-key chatty grab`

## Task 8 — Compose a ticket from the phone (`c`)

**Goal:** new issue in two dictated fields.

- From `modeBacklog`, `c` → compose. Zero github repos in scope →
  flash "no github repos in this workspace", stay. One → straight to
  form; >1 → repo picker first.
- Form: title = `textinput`, body = **`textarea`** (bubbles ships it;
  dictated bodies need paragraphs) — embedded bubbles, the detail-reply
  pattern; never `huh.Form.Run()` inside the live program. Then a
  confirm screen rendering the issue → `y` runs `gh issue create
  --title … --body …` with **`cmd.Dir = repo.Path`** (no `-R`; config
  has no owner/repo slug — same cwd resolution as the provider,
  `github.go:39-51`) via an injected `CreateIssue` func var.
- Success → flash the issue URL + "grab it now? y/n"; `y` extracts the
  number from the printed URL (`ghURLRe` pattern, `github.go:57`) and
  reuses task 7's `RunGrab`. Failure → flash last stderr line, **form
  state preserved** for retry. `esc` at confirm returns to edit, not
  discard.
- Propose-then-dispose: nothing sent before `y`. Issue creation is not
  a terminal-state mutation (hard rules intact).
- **Tests:** update-machine with faked `CreateIssue`: happy path,
  failure preserves title/body, esc-at-confirm returns to edit,
  zero-repo flash, URL→number extraction.

**Commit:** `tui: compose github issue from backlog view`

## Task 9 — Mobile keybind diffs + idle throttle

**Goal:** the phone client can never wander; a phone-less Mac stays
quiet.

- Mobile mode (`opts.Mobile`):
  - `a` → flash "attach is desk-only — enter opens the pane tail"
    (never `switch-client`). Detail view's PANE section grows:
    `CapturePaneBottom(…, n)` where n fills `m.height` minus chrome
    (today fixed 14, `tui.go:147`).
  - `O`/`0` → flash "orchestrator chats live on the desk cockpit".
  - Footer renders the mobile key set only (fits 45 cols).
- Idle throttle — **mobile mode only** (the session name is the
  constant the helper needs): `grove.go` helper
  `SessionHasClients(name) bool` (`tmux list-clients`); tick closure
  picks 1s attached / 30s detached at schedule time; PR tick 30s → 5m
  detached. Desktop keeps today's cadence.
- **Tests:** pure `tickInterval(mobile, attached bool)` table;
  handleKey mobile table (`a`/`O` flash, no Cmd); footer width test at
  45 cols.

**Commit:** `tui: mobile keybind guards + detached idle throttle`

## Risks / watch-fors

- **`pane_start_command`** is present on tmux 3.6a (the Mac's version);
  the `pane_current_command` fallback in task 6 covers older hosts.
- **Two TUIs, one state dir** (desk cockpit + mobile on the same
  workspace) is already safe — events.jsonl is O_APPEND+flock and both
  poll — but worth one dummy.sh assertion (append from two processes,
  fold once).
- The TUI package is a recorded divergence from ovs; this plan widens
  it substantially. Intended (grove is the successor) — but
  `internal/tmux/tmux.go` stays untouched.
