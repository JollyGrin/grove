## Scope decisions (made here, per seed-manifest generalization map)

- **State stays global for P0.0** (`~/.local/state/grove/`, env
  `GROVE_STATE_DIR`) — the per-workspace `.grove/state/` move is Phase 1
  (workspace registry). Seed manifest explicitly allows this interim.
- **`ccwork` / `~/.cc-work` are NOT renamed.** They are the shared worker
  Claude profile, deliberately shared with live ovs during the transition
  window (dual-hook design, DESIGN.md §12). Only the env var
  `OVS_CLAUDE_CONFIG_DIR` → `GV_CLAUDE_CONFIG_DIR` renames (it's gv's own
  knob, not the profile's name).
- **`internal/linear` stays byte-comparable**; the adapter lives in a new
  `internal/provider` package. `internal/kickoff`, `internal/config`,
  `internal/hooks`, `internal/audit`, `cmd/gv/main.go`, `internal/tui`,
  `internal/doctor`, `orchestrator/CLAUDE.md` diverge deliberately —
  each divergence recorded in docs/seed-manifest.md.
- **Minimal `gv init` is in scope** (deterministic scaffold only: register
  repo in global config + create `.grove/tasks/` + sample task). The full
  probe/wizard/AGENTS.md bootstrap stays Phase 1. Rationale: "test from
  any repo" is the acceptance; without init the first-run is hand-editing
  YAML.
- **`ovs.go` filenames stay** (rename-when-generalizing rule). The
  `ovs-relay` tmux buffer name → `gv-relay` (isolated, zero-risk).
- **Grid-specific doctor checks stay live in P0** (ccwork plugins,
  universal CLAUDE.md symlink, LINEAR_API_KEY, zsh alias probe). They are
  read-only and correct on Dean's machine; `gv doctor` on a stranger's
  markdown repo will show irrelevant rows until Phase 1b derives doctor
  from the connections manifest. Acknowledged noise, not a bug.

## Task 2 — `internal/provider`: interface + linear adapter + markdown provider (TDD)

New package `internal/provider`:

```go
type Comment struct{ Author, Body string; CreatedAt time.Time }
type Task struct {
    ID, Title, Description, URL string
    Labels   []string
    Comments []Comment
    Status   string // provider-native; markdown: backlog|todo|in-progress|review|done
}
type Verbs struct{ Start, Review string } // prose instructions rendered into kickoff
type Capabilities struct{ CanList bool }
type Provider interface {
    Kind() string
    ParseID(raw string) (string, error)
    Get(id string) (*Task, error)
    List() ([]*Task, error) // grabbable backlog (markdown: status backlog|todo)
    Verbs() Verbs
    Capabilities() Capabilities
}
```

**Deliberate P0 subset of DESIGN §5.1** (recorded in seed-manifest):
`Attach(taskID, prNumber)` and the fuller `Capabilities{canTransition,
canComment, hasRemote, autoLinksPR}` are deferred — P0 has no write path
that needs them, and adding dead surface now would fake-satisfy the
Phase 3 seam stress test. `Capabilities` keeps only what P0 reads
(`CanList`).

- `linear` adapter wraps `internal/linear` (which stays byte-comparable):
  `ParseID` = `linear.ParseIdentifier(strings.ToUpper(raw))`, `Get` =
  `FetchIssue`, `List` = unsupported for P0 (`CanList: false`), verbs =
  the dev-linear MCP instructions (text lifted from today's template).
- `markdown` provider: rooted at a dir (`<repo>/.grove/tasks` default,
  config-overridable). One file per task, YAML frontmatter per DESIGN.md
  §5.2 (`id,title,status,priority,labels,assignee,dependencies,created,pr`)
  + markdown body. `Get` by id (file `<id>.md`, fallback scan by
  frontmatter id). `List` = status `todo|backlog`, **excluding tasks grove
  already has in flight** (caller passes active-task ids — event-state is
  authoritative, DESIGN §5.2). `ParseID` = lowercase, validate
  `[a-z0-9][a-z0-9-_]*`. Verbs: Start = "edit `.grove/tasks/<id>.md`, set
  `status: in-progress`, commit on your branch"; Review = same with
  `status: review`.
- Frontmatter parsing: split `---` fences, `yaml.Unmarshal` (dep already
  present). Malformed file → clear error naming the file.
- Config: new `provider:` section — `kind: markdown|linear` (default
  **markdown**), `markdown: {dir}`, existing `linear:` block feeds the
  linear adapter. `config.Load` defaults preserved.

**TDD:** table tests for frontmatter parse (happy, missing fields,
malformed, status filter, in-flight exclusion), ParseID validation, and
provider selection from config.

**Verify:** `go test ./internal/provider/...` green.

## Task 3 — rewire grab/adopt/findTask through the provider; kickoff verbs

- `cmdGrab`: resolve provider from config. For `markdown`, resolve the
  repo **first** (`--repo` or sole configured repo; ambiguous → error
  listing options) since the provider roots at the repo; for `linear`,
  keep today's fetch-then-label-inference order. `gv grab` with no args:
  if `CanList`, print the grabbable backlog (id · title · priority) and
  exit; else today's usage error.
- `cmdAdopt` + `findTask`: id normalization goes through
  `provider.ParseID` (drops the hardcoded `ToUpper`+Linear regex for
  markdown ids).
- **No-remote grab (plan-review C-1):** grab currently runs
  `git.Fetch(origin, base)` + `worktree.Add(…, "origin/"+base)`, which
  fails fatally in a repo with no remote. Add a base-resolution step: if
  `git remote get-url origin` fails, skip the fetch and branch the

  the base-resolution helper (remote present / absent / base branch
  missing → clear error).
- Fold the `finishTask` success-message Linear-ism
  ("Linear status is yours to move", main.go:1171) into provider-aware
  wording.
- `internal/kickoff`: `Render` takes `provider.Task` + `Verbs`. Template

## Task 4 — `done` degraded path (no-remote)

In `finishTask`: if the repo has no usable remote (`git remote get-url
origin` fails) or the branch was never pushed, the `gh pr view` merge
check is impossible — print exactly why and require `--force` as the
human confirmation (DESIGN §5.2 degraded semantics). No behavior change
for repos with remotes. Unit-test the branch classification helper.
Together with Task 3's no-remote grab fallback, this makes the entire
no-remote loop coherent: the E2E repo stays remote-less end-to-end
(grab branches from local base; done degrades to `--force`).

## Task 5 — minimal `gv init` (deterministic scaffold)

`gv init` run inside a git repo:

1. Refuse outside a git repo (clear error).
2. Derive repo name (dir basename) and base branch (current default via
   `git symbolic-ref refs/remotes/origin/HEAD`, fallback `main`).
3. Global config `~/.config/grove/config.yaml`: create with
   `provider: {kind: markdown}` if missing; add `repos.<name>` entry
   (path, base, `claude:` default) if absent; if present, no-op and say
   so. YAML round-trip via unmarshal/marshal is acceptable (no legacy
   grove configs exist to preserve comments in).
4. Scaffold `.grove/tasks/` + `task-001.md` sample (only if the dir
   doesn't exist).
5. Print next steps (`gv doctor`, edit sample task, `gv grab task-001`).

Idempotent: running twice changes nothing. TDD: init-into-temp-repo test
covering fresh config, existing config, re-run.

**Non-goal:** probe/wizard/AGENTS.md — this is a scaffold, not Phase 1.

## Task 6 — E2E: dummy-data pattern, committed as a script

`e2e/dummy.sh` (bash, set -euo pipefail): scratch `HOME`, scratch
`GROVE_STATE_DIR`, scratch git repo (with a commit, **no remote** — the
whole run exercises the degraded no-remote loop per DESIGN §5.2),
`gv init`, rewrite the repo's `claude:` to `echo`, then:

- `gv grab` (no args) lists the sample task
- `gv grab task-001` → assert worktree exists at
  `<parent>/.worktrees/<repo>/task-001-*`, tmux window exists, prompt file
  written, `gv ls --json` shows the task
- `gv hook stop` with a JSON payload whose cwd is an **untracked** dir →
  exit 0, `events.jsonl` unchanged (dual-hook ownership contract)
- `gv untrack task-001 --rm` → worktree/window gone
- `gv done` degraded path: grab again, then `gv done task-001` fails
  without `--force` (no remote), succeeds with it
- cleanup traps kill the scratch tmux session

Assert throughout that no file under the real `~/.local/state/overstory`
or `~/.config/overstory` was touched (stat mtimes before/after).

## Risks / FMA

| Risk | Mitigation |
|---|---|
| Rename misses a path and gv touches live overstory state | Inventory-driven checklist (Task 1) + E2E asserts overstory paths untouched + grep gate |
| Grab fails on a repo with no remote (`origin/<base>` base) | Task 3 base-resolution fallback to local base; E2E repo is remote-less end-to-end |
| `gv hooks install` mangles live ovs hooks in shared settings.json | TDD on the detection predicate; never-match-ovs asserted; **no live write this session** — Dean runs `gv hooks install` in the morning |
| Markdown ids break branch/window naming somewhere unnoticed | ids validated slug-safe at ParseID; E2E exercises the full grab path |
| Kickoff generalization silently changes linear behavior | golden byte-parity test for the linear render |
| `gv init` YAML rewrite clobbers a hand-edited config | init only ever *adds* missing keys; no-op when repo exists; unit tests |
| Worker command default (`ccwork`) absent on a stranger's machine | Out of scope for P0 (Dean's machine has it); doctor already flags it; config `claude:` overrides |
